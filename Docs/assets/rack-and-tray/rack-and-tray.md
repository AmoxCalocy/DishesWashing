# 沥水架与待洗托盘

2026-11-17 使用 Blender 5.3.0 CLI 制作。木质沥水架提供六个竖放餐盘槽与两个倒扣马克杯位，圆角待洗托盘可同时摆放两个标准餐盘和一个马克杯。槽位按已交付餐具的实际网格验证。

## 尺寸与结构

| 项目 | 尺寸或做法 |
| --- | --- |
| 主沥水架 | 宽 540 × 深 400 × 高 200 mm，圆角木框与镂空承托条 |
| 前侧杯区 | 宽 340 × 深 140 mm，三根横条供杯口承托、通风 |
| 包含杯区的总占地 | 宽 540 × 深 575 mm；杯区是同一资产下的独立模块 |
| 餐盘槽 | 六槽，中心距 73 mm；隔柱厚 14 mm，顶桥厚 16 mm，最窄净间距 57 mm |
| 竖盘支撑面 | 根节点以上 36 mm，中央横条承托餐盘最低盘沿 |
| 倒扣杯支撑面 | 根节点以上 27.5 mm，杯柄统一朝 +X，两杯中心相距 165 mm |
| 待洗托盘 | 宽 610 × 深 490 × 高 48 mm，开放内腔、圆角包边、四个底垫 |
| 托盘内底 | 566 × 446 mm 的圆角区域，圆角半径 32 mm；平面高于根节点 12 mm |
| 展示支撑余量 | 餐具最低接触点比对应承托面高 0.5 mm，避免预览共面闪烁 |

沥水架为 **4,704 个源顶点、9,212 个三角形、9 个网格、21 个节点**；托盘为 **904 个源顶点、1,788 个三角形、2 个网格、9 个节点**。各有三个基础 PBR 材质，全部网格已展开 UV，无外部贴图依赖。木架使用深浅木色，尚未加入木纹贴图；托盘使用暖白搪瓷色、橄榄绿包边与深色底垫。

重复木件按功能合并为可编辑网格岛，接头保留正常的实体搭接。杯区是可单独调整的 `Cup_Drain_Area` 子节点。这里没有集水模拟或自动排水效果。

## 原点与安装

两个 GLB 的资产根节点均位于原点、保持单位缩放。原点高度对应台面接触面；不要使用旧灰盒占位的几何中心高度。

| 资产根节点 | Blender 世界位置 | Godot 世界位置 |
| --- | --- | --- |
| `Dish_Rack` | `(0.88, 0.035, 0.90)` | `(0.88, 0.90, -0.035)` |
| `Dirty_Tray` | `(-0.89, -0.025, 0.90)` | `(-0.89, 0.90, 0.025)` |

共用 `.blend` 中，两根节点已位于上述安装位置，便于查看两侧布局；GLB 导出在移动根节点之前完成，所以导入游戏后需分别设置安装位置。坐标映射为 Blender `(x, y, z)` → Godot `(x, z, -y)`。

主架左边界为世界 `x=0.61`，与洗洁精瓶外侧约留 36 mm；待洗托盘右边界为 `x=-0.585`，与水槽最左缘约留 105 mm。杯区最前端为 `y=-0.34`，距台面前沿约 60 mm。

下表是相对资产根节点的 **Blender 局部坐标**，单位为米。餐具槽节点保存了完整的餐具根节点位置和旋转，不能再叠加餐具半高。

| 定位节点 | 局部位置与方向 |
| --- | --- |
| `Rack_Slot_01`～`06` | `x=-0.1825 + 序号×0.073`（序号 0～5）、`y=0`、`z=0.1615`；绕 Blender Y 轴旋转 90°，餐盘正面朝 +X |
| `Rack_Cup_Slot_01` | `(-0.045, -0.305, 0.0805)`；绕 X 轴旋转 180°，杯口向下、杯柄朝 +X |
| `Rack_Cup_Slot_02` | `(0.12, -0.305, 0.0805)`；同上 |
| `Dirty_Plate_01` / `02` | `(-0.137, -0.06, 0.0245)` / `(0.137, -0.06, 0.0245)`；餐盘正面向上 |
| `Dirty_Mug_01` | `(0, 0.14, 0.065)`；杯口向上、杯柄朝 +X |
| `Tray_Interior_Surface` | `(0, 0, 0.012)`，内底表面参考，不是餐具根节点位置 |
| `Rack_Interaction` / `Dirty_Pickup` | `(0, -0.20, 0.11)` / `(0, -0.06, 0.11)`，交互区域参考 |

在 Godot 中，将现有 `Plate_Standard` 或 `Mug_Standard` 实例的 `global_transform` 复制为对应槽节点的 `global_transform` 即可复现预览姿态。以后若单独移动杯区模块，还应同步移动两个杯槽节点；它们当前直接隶属 `Dish_Rack`。

这些节点只描述目标位置。槽位占用、可放置预览、吸附、拿取、堆叠和碰撞处理仍需由游戏逻辑实现。用脏污材质决定待洗状态，托盘预览中的素色餐具只用于检查尺寸。

## 验证与范围

- 检查各网格岛的闭合性、非退化面、朝外法线和 UV。
- 用实际餐盘与杯体、杯柄网格，在全部 11 个位置检查餐具之间以及餐具与架体、托盘之间的三角面相交；未发现穿插。
- 从餐具最低处向下发射射线，确认各位置存在约 0.5 mm 下方的承托面；托盘从上方射线可命中内底，内腔未封闭。
- Godot 4.7.2 成功读取两个 GLB，验证节点层级、米制尺寸、UV、法线、材质及三角形数量；导出未包含预览相机、灯光或餐具副本。
- 在 Godot 中按 11 个槽位实际放置餐盘、马克杯实例，验证竖盘、倒扣杯、平放盘与直立杯的朝向，以及与 Blender 一致的最低点高度。
- 正前方相机以水槽为中心，两侧外缘会超出画面；左右环顾预览保持玩家原站位和视野角度，分别检查完整餐具区域。游戏内需允许相应环顾范围。

以上检查针对预设静态姿态，没有验证动态插入轨迹、重力下的稳定性或任意旋转放置。后续碰撞体应保留架槽、通风缝和托盘内腔，不能给整个架体或托盘使用一个封闭凸包。

`01_Dish_Rack_Asset` 和 `02_Dirty_Tray_Asset` 为正式模型集合。`90_Preview_Studio` 含布光与现有餐具的展示副本，餐具默认隐藏，不进入两个 GLB；正式餐盘和马克杯仍使用原有资产。操作区预览只在内存中替换灰盒占位，原灰盒和其他模型没有被覆盖，正式主场景整体组装仍待进行。预览由 Blender 渲染，Godot 实时灯光下的材质表现需在接入时复核。

## 重建

在项目根目录运行，会覆盖本轮共用 `.blend`、两个 `.glb` 与八张预览。脚本读取已有灰盒、餐盘、马克杯、水槽、水龙头、泵瓶和海绵源文件。手动修改后应先保存编辑版本，再运行重建。

```powershell
& 'D:\Blender\blender.exe' --background --factory-startup --python-exit-code 1 --python 'Tools/build_rack_and_tray.py'
```
