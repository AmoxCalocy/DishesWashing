# 游戏设计文档：洗碗时光

> 版本：0.1｜状态：概念与原型设计｜日期：2026-11-06

## 1. 游戏概述

**《洗碗时光》**是一款单人第一人称 3D 休闲模拟游戏。玩家在温暖的厨房里接收脏餐具，通过冲洗、涂抹洗洁精、擦洗和摆放完成一轮清洁。随着关卡推进，餐具形状和污渍组合逐渐变化，玩家解锁新的场景装饰与工具外观。

- **核心体验**：把凌乱的水槽一点点整理干净，享受可见的清洁反馈和完成感。
- **目标玩家**：喜欢整理、清洁模拟及舒缓短局游戏的玩家。
- **目标平台**：PC，键盘与鼠标；手柄支持作为后续目标。
- **单局时长**：约 5～10 分钟，可暂停。
- **美术方向**：柔和、略带风格化的写实厨房，避免恐怖或脏污刺激感。
- **商业模式**：暂定买断制；本文不设计内购或联网服务。

以上为初版设计假设，具体平台、题材和美术风格可根据原型测试调整。

## 2. 设计目标与原则

1. **清洁过程清晰可感**：污渍随擦洗逐步消失，声音、泡沫和水流共同反馈进度。
2. **操作简单但有空间感**：拿起并旋转餐具，找到污渍和合适的擦洗角度。
3. **节奏由玩家掌控**：默认没有倒计时；可选挑战模式提供时间目标。
4. **每局都有明确终点**：完成订单并整理台面后结算，避免无止境的重复劳动。

## 3. 核心循环

**接取订单 → 查看餐具和污渍 → 拿起餐具 → 冲洗或涂抹洗洁精 → 擦洗 → 检查清洁度 → 放入沥水架 → 完成订单 → 获得奖励并解锁内容。**

玩家可在清洗过程中自由切换餐具和工具。订单中的全部餐具达标且放入沥水架后，玩家主动点击“完成订单”结算；未达标时，扣除相应的奖励。

## 4. 操作与视角

玩家站在水槽前，视角可在限定范围内转动；工作区内通过准星选择可交互物体。原型先采用固定站位，避免移动与拾取同时增加操作负担。

| 输入 | 操作 |
| --- | --- |
| 鼠标移动 | 环顾；持有工具并按住左键时，在餐具表面移动工具 |
| 鼠标左键 | 拾取或放下餐具；持工具时按住使用 |
| 鼠标右键按住并移动 | 旋转手中的餐具 |
| 鼠标滚轮 | 调整手持餐具距离，限制在可操作范围内 |
| E | 与水龙头、洗洁精瓶、订单板等交互 |
| 1 / 2 / 3 | 切换空手、海绵、喷头；按当前工具键可收起工具 |
| Q | 放回手持餐具至水槽或台面上的有效位置 |
| Tab | 查看订单与每件餐具的清洁进度 |
| Esc | 暂停、设置或退出当前订单 |

拿起餐具后，它保持在镜头前的操作区域；使用工具时餐具仍被固定，玩家可随时右键旋转。瞄准沥水架有效槽位并点击左键可放入餐具。无有效落点时给出提示，不让餐具掉出可操作区域。交互提示只在物体可操作时出现。

## 5. 清洁机制

### 5.1 污渍与工具

每件餐具可包含多个污渍区域，每个区域记录剩余污渍量。原型包含两种污渍：

| 污渍 | 外观 | 处理方式 |
| --- | --- | --- |
| 食物残渣 | 小块、边缘不规则 | 喷水或湿海绵均可清除，喷水更快 |
| 油渍 | 半透明暖色薄层 | 先涂洗洁精，再用海绵擦洗；仅喷水效果很弱 |

海绵默认可用；与洗洁精瓶交互后，海绵获得洗洁精。喷头和海绵在准星接触餐具表面且玩家按住左键时生效。原型不模拟洗洁精耗尽、水费或细菌。

### 5.2 判定与反馈

- 工具持续接触污渍时，按时间减少对应区域的污渍量；擦洗需要玩家移动鼠标，避免静止按住即可完成全部清洁。
- 初始调参目标：普通餐盘约 30～60 秒洗净；具体数值以试玩为准。食物残渣被水冲掉后，油渍仍可能留存。
- 清洁度按各污渍区域的初始污渍量加权计算：`清洁度 = 1 - 剩余污渍总量 / 初始污渍总量`。无初始污渍的餐具视为 100%。
- 进度显示为整数百分比，达到阈值时给出柔和提示音与视觉提示。
- 每次有效清洁都有局部污渍变化、接触音和适量泡沫或水花；无效操作通过简短提示说明，例如“油渍需要洗洁精”。
- 首次教学允许开启污渍高亮；之后可在设置中随时开启。高亮只提示位置，不代替清洁操作。

### 5.3 安全与容错

餐具不因掉落或用力过大而破碎；放错位置可以重新拿起。玩家可以暂停、重置当前订单或退出，重置前弹出确认。原型不引入物理惩罚或隐藏污渍。

## 6. 订单、关卡与进度

### 6.1 首次体验

1. 简短提示视角和拾取操作，玩家拿起一个盘子。
2. 喷水去除明显残渣，学习旋转餐具查看背面。
3. 给海绵涂洗洁精并擦除油渍，观察清洁度。
4. 将餐具放到沥水架，完成订单并查看结算。

教学提示在完成对应动作后消失，可跳过，并可从菜单重新查看。

### 6.2 关卡示例

| 订单 | 内容 | 引入的变化 | 预计时长 |
| --- | --- | --- | --- |
| 初次清洗 | 1 个盘子 | 拾取、冲洗、擦洗、摆放 | 2～3 分钟 |
| 早餐之后 | 2 个盘子、1 个杯子 | 杯内与背面污渍 | 5～7 分钟 |
| 家庭晚餐 | 2 个盘子、2 个杯子、1 个碗 | 混合污渍和更多摆放位置 | 8～10 分钟 |

订单从已解锁列表中选择，可重复游玩。完成前一订单解锁下一订单；完成订单授予固定数量的装饰点数，首次完成可额外奖励。点数仅用于购买海绵颜色、餐垫等外观，不影响清洁效率。原型可先不实现商店，结算时展示预留点数。

### 6.3 结算与可选挑战

结算展示完成餐具数、平均清洁度、用时和获得的点数；提供重玩、下一订单和返回菜单。普通模式不按用时扣分，也没有失败状态。

后续可加入独立的限时挑战：时间结束即结算已完成餐具，不阻断普通模式进度。挑战规则和奖励需在开始前说明。

## 7. 场景、界面与音画

### 场景

首个场景为一间阳光柔和的小厨房。可交互区域包含水槽、水龙头、洗洁精瓶、工具收纳处、沥水架与订单板。餐具和工具的轮廓、颜色应与背景区分；污渍在不同光照下仍能辨认。

### 界面

- **主菜单**：开始、订单选择、设置、退出。
- **游戏中**：中央准星、当前工具、上下文交互提示；拿起餐具时显示名称及清洁度。
- **订单面板**：列出餐具、完成状态及剩余数量。
- **结算界面**：展示结果、奖励和下一步操作。
- **设置**：音量、鼠标灵敏度、视角反转、字幕、污渍高亮、画面质量与分辨率。

UI 默认保持简洁；关键信息不只依靠颜色区分，文字与图标应有足够对比度。避免强闪烁，允许关闭非必要屏幕抖动。

### 声音

水流、海绵摩擦、陶瓷轻碰和放入沥水架的声音构成主要反馈。背景音乐轻柔且可单独调节；持续水声应避免刺耳或过大。关键状态变化配合字幕或文字提示，不依赖声音传达。

## 8. 技术方案与存档

引擎尚未确定。原型优先验证交互与清洁体验，再根据团队经验和目标平台选择引擎。建议将餐具配置、污渍区域、订单和奖励数据分离，以便调整内容。

- **交互**：从摄像机发射射线识别可交互物；手持餐具使用受限旋转，工具接触点映射到餐具表面。
- **污渍表示**：先用少量可独立清除的区域或遮罩实现；若需要连续擦除，再评估纹理遮罩方案的性能和实现成本。
- **物理**：放置使用预设槽位吸附，减少餐具穿模和意外滚落；必要时才启用完整刚体模拟。
- **存档**：本地保存设置、已解锁订单、点数及外观。订单完成时自动保存；首版不保存进行中的订单，退出前明确提示进度将重置。
- **性能目标**：目标硬件待确定；原型先在团队现有中端 PC 上追求稳定 60 FPS，并记录分辨率和画质设置。

## 9. 最小可玩版本（MVP）

MVP 的目标是验证“观察污渍—动手清理—看见成果”是否令人满足，而不是覆盖所有扩展功能。

**包含**：一个固定站位厨房、盘子和杯子两种餐具、食物残渣与油渍、喷头和海绵、洗洁精、清洁度反馈、沥水架、一个可重复订单、简单教学与结算、暂停和基础设置。

**暂不包含**：角色移动、餐具破碎、商店与外观购买、限时挑战、多个场景、手柄、联网和复杂水流模拟。

**验收标准**：

1. 新玩家无需开发者指导，能在教学提示下完成一件正反面均有污渍的餐具。
2. 残渣可被喷水清除；油渍需要洗洁精与海绵有效配合。清洁进度与视觉变化一致。
3. 清洁度达到 95% 的餐具可以放入沥水架；未达标餐具不会被计为完成。
4. 所有餐具完成后可主动结算、重玩；暂停、重置和退出提示符合设计。
5. 一次完整订单中，餐具和工具不会丢失到无法取回的位置；帧率、分辨率与测试硬件均有记录。

## 10. 制作阶段与验证

| 阶段 | 交付物 | 验证重点 |
| --- | --- | --- |
| 交互原型 | 灰盒水槽、拾取、旋转、放置 | 视角是否舒适，操作是否易懂 |
| 清洁原型 | 污渍、工具、清洁反馈 | 擦洗是否有满足感，污渍是否易辨认 |
| 完整一局 | 教学、订单、结算、暂停 | 新玩家能否独立完成，单局节奏是否合适 |
| 内容与打磨 | 更多订单、音画、进度与设置 | 重复游玩意愿、可访问性与性能 |

每阶段邀请少量未参与开发的玩家试玩，观察完成时间、卡住的位置、误操作和主观舒适度；根据结果调整阈值、清洁速度及提示，而非预先锁定数值。

## 11. 主要风险与待决定事项

- **擦洗重复或疲劳**：通过变化餐具形状、污渍位置和短局长度验证趣味；必要时增加按键替代或降低所需鼠标移动量。
- **旋转和表面定位困难**：先测试固定站位与受限旋转，提供灵敏度设置和污渍高亮。
- **污渍遮罩成本过高**：从区域式污渍开始，用原型性能数据决定是否升级为连续纹理擦除。
- **待决定**：引擎、具体目标硬件、最终美术风格、无障碍操作方案、内容量及发行平台。它们应在 MVP 试玩后结合团队资源确定。
